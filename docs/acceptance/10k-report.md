## 端到端冒烟

后端闭环通过真实 `LibraryService`、真实临时资料库和真实 SQLite 自动执行：

1. 创建资料库。
2. 导入覆盖六种支持格式的一万份文档。
3. 创建集合和标签，批量移动、批量加标签并更新文档元数据。
4. 执行中文、英文、短查询和组合筛选。
5. 读取 TXT 文档预览。
6. 外部修改 121 份资料库副本，其中 1 份构造为损坏 PDF。
7. 重启后执行增量扫描和重新索引，验证成功与失败项。
8. 将 100 份文档移入回收站，恢复 50 份，永久删除 50 份。
9. 关闭服务并移出最近列表，确认资料库目录及其数据不被删除。
10. 校验全部源文件字节未发生变化。

真实 GUI 未使用原生指针或 Tauri WebDriver 驱动执行。当前项目未配置 Playwright、WebDriver 或桌面端截图基线；因此本轮不声称完成原生 GUI 自动化。React/jsdom 测试覆盖一万份数据下的初始 DOM 窗口、模拟滚动增量加载、网格切换和索引进度显示；这不等于真实窗口滚动、元素重叠检查或长时内存曲线验证。后端闭环不因此跳过。

## 发现并修复的问题

| 影响 | 问题 | 修复 |
| --- | --- | --- |
| 高 | 索引循环反复扫描并排序剩余待处理文档，10k 规模接近二次复杂度 | 增加活动导入顺序索引和待处理队列索引 |
| 高 | 列表、搜索和回收站为每份文档单独查询标签，10k 规模产生上万次 SQL | 使用一次批量 CTE 查询装配全部文档标签 |
| 高 | 列表和网格一次渲染全部 10k 行/卡片，且逐项线性搜索完整搜索结果 | 首批最多渲染 200 项，滚动邻近底部时每批增加 200 项；搜索结果与集合改为 `Map` 查找 |
| 中 | 索引阶段只有旋转提示，没有已处理数量 | 后端每 100 份发送一次处理进度事件，前端显示 `processed/total`；实际索引仍在阻塞任务中执行，不占住 UI 事件循环 |
| 高 | 永久删除先执行 DB 删除再删除资料库副本；提交失败或进程中断可能丢失副本 | 先在同一文档目录重命名为 tombstone，再提交 DB；失败立即恢复，成功后清理 tombstone，打开资料库时按 DB 状态恢复或清删遗留 tombstone |
| 高 | 清空回收站遇到单项失败会整体中止，UI 无法知道哪些项已删、哪些仍可重试 | 后端逐项返回成功/失败；前端显示部分失败明细并保持对话框打开，失败项继续留在回收站供重试 |
| 高 | 启动/打开一致性检查仅在大小或时间戳变化时计算哈希，同大小同时间戳改写会漏检 | 打开资料库时对全部活动副本执行内容哈希核对；运行期仍使用可合并的轻量指纹监视 |
| 中 | 索引进度 total 来自导入前文档快照，导入后可能显示 `0/0`；无 `item` 或无 `result` 的事件不更新文档状态 | 新增后端实时待索引计数；前端用 `documentIds`/进度事件立即显示“处理中”，完成后刷新真实文档状态 |
| 高 | 图片缩略图直接传输完整原文件，PDF 网格用完整 PDF iframe 冒充首页缩略图，详情预览持续累积完整 PDF 对象 | Rust 使用 WIC 生成受限尺寸 PNG、使用 `Windows.Data.Pdf` 渲染 PDF 首页并按内容版本缓存；网格改为真实图片；详情按页创建和撤销受控对象 |
| 高 | `start_import` 是同步命令，10k 导入约 62 秒持续占用 IPC 执行线程 | 整批导入和 `LibraryService` 加锁移入 Tauri `spawn_blocking` 工作线程，保持单服务串行访问；命令层测试验证服务锁被占用时任务调用仍立即返回 |
| 中 | 外部改写后 document id 不变但 contentHash 变化时，网格缩略图和详情预览 effect 不会重新请求 | 缩略图和详情预览依赖 contentHash、文件大小和最近导入时间；同 ID 新 hash 回归测试覆盖重新请求、PDF 新 object URL 创建及旧 URL 撤销 |

- `src-tauri/tests/library_service.rs`：验证 `800×600` PNG 被缩放为 `320×240` 的真实 PNG、PDF 首页输出为真正的图片 data URL、缩略图缓存复用，以及损坏图片降级为类型图标。
- `src-tauri/src/commands.rs`：命令层测试验证 `start_import` 的 blocking task 在服务锁被占用时仍立即返回，并在释放锁后完成导入和进度回调；不声称该测试测量了原生 GUI 响应。

## 限制与后续事项

- 首次导入和首次索引在 debug 构建下存在明显波动：早期结果各约 62 至 63 秒，HEAD `80ec990` 最终复测分别为 87.176 秒和 86.313 秒。报告中的耗时均不替代 release 性能测量；当前 `start_import` 已通过 `spawn_blocking` 调度，命令层测试验证服务锁被占用时任务调用仍立即返回，进度回调能够完整执行。本轮仍没有真实原生 GUI 响应测量、release 构建耗时，也没有用户可感知的取消索引能力，因此“应用不会长时间无响应”不能据此判定通过。
- 全量哈希启动核对将 10,000 份文档的重启检查增至约 4 秒。该耗时用于保证同大小且时间戳不变的资料库副本改写不会漏检，属于当前数据安全取舍。
- 本轮将 DOM 首屏限制在 200 项并用 jsdom 验证模拟滚动增量加载，但没有执行真实原生窗口滚动、绘制、截图差异或长时间内存采样；因此只能确认初始 DOM/状态规模受控，不能据此宣称任何操作序列下内存曲线绝对平坦。
- PDF、DOCX 使用可解析的最小合成文件，足以覆盖格式识别、正文提取和索引路径，但不代表复杂真实文档的解析性能。
- 缩略图回归只使用小型有效 PNG 和单页最小 PDF，验证的是真实解码、缩放、首页渲染和失败降级路径，不代表大批量复杂 PDF 的渲染吞吐或对象内部内存已经完成 soak 验收。
- 原生 GUI、鼠标、键盘和截图级视觉验收未自动化。若后续引入 Tauri WebDriver/Playwright，应复用同一 10k 资料库增加窗口级滚动和内存验证。

## 判定

HEAD `80ec990` 的自动化后端闭环和 React/jsdom 规模测试通过，工作单 12 本身不能标记为全部完成。最终复测总耗时 223.98 秒，早期 150.110 秒作为 debug 环境波动记录保留；新结果不覆盖旧结果，也不改变 release 性能未验收的结论。高影响索引、标签查询、前端 10k DOM 窗口、索引进度、永久删除安全、清空回收站部分失败、外部变化漏检、真实缩略图，以及异步导入命令路径和同 ID 新 hash 预览刷新问题均已修复并有回归覆盖；首次导入与索引的原生 GUI 响应性、真实滚动内存、release 性能和复杂真实文件覆盖仍未完成，对应验收项必须保持未勾选。
