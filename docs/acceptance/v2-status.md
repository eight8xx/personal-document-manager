## 三、本版新增的关键设计

- **契约先行**：格式能力表（`shared/document-format-capabilities.json`）扩到 9 种格式（新增 CSV、XLSX），前后端共用；表格预览、分类规则、接收目录三份契约在动手前冻结，两端并行实现后一次合并通过。
- **表格文档**：`library/table.rs` 纯解析层（零新依赖，复用最小 ZIP 读取器 + flate2），支持多工作表、共享字符串、稀疏行（保留真实 Excel 行号 `<code>row_numbers</code>`）、公式只读缓存值、CSV 引号/换行/BOM；拒绝旧 XLS、加密容器、ODS、XLSM、XLSB 并给出具体原因。
- **资源上限**：`library/limits.rs` 统一输入大小、单条目声明、压缩比、累计解压量与表格行列上限；DOCX/PPTX/XLSX 的 ZIP 读取在解压前校验；正文提取有字符上限并显式标注截断。
- **导入让锁**：批量导入从「整批一把锁」改为「每项一把锁」，读取（列表/搜索/预览）不再排队到整批结束；每项执行前重新核对资料库身份，中途切库时该批以 `invalidLibrary` 结束，已完成项留在原库、新库零写入。
- **资料库级数据**：分类规则、接收来源、用户明确跳过的源文件、接收导入日志都存进资料库 SQLite（`library/store.rs`），随资料库迁移，不写应用级状态。

## 四、工作单 07 的暂停说明

07 剩余的唯一验收条目要求自动化驱动**真实原生文件选择器 / 首次向导 / 导入按钮**。在当前环境下这需要在用户日常使用的交互式桌面上注入鼠标与键盘输入（tauri-driver + WebDriver，或 Win32 消息驱动原生对话框）。本轮尝试时占用了用户桌面，已被用户要求停止，脚本未提交并已删除，过程记录在 `issues/07-native-smoke-test.md`。

当前可复现的部分：`npm run test:native-smoke` 仍能在真实 Windows 窗口中跑通 9/9 步（含 TXT 导入后的集合整理、搜索、预览、回收站与恢复），覆盖标志 `nativeFilePickerCovered`、`libraryWizardCovered`、`importButtonCovered` 均为 `false`，不得据此签收。剩余部分需要：① 人工按文档执行并记录；② 在独立测试机/虚拟机执行；或 ③ 明确接受该条长期未覆盖。

## 五、已知边界（有意保留，未假装解决）

- **单文件粒度**：让步粒度是「每项」，单个超大文件处理期间读取仍会等这一项，不会等整批。
- **PDF 侧解压上限**：04 只覆盖 DOCX/PPTX/XLSX 的压缩包读取；`extract_pdf_text` 与 `pdf_security.rs` 的流解码仍无统一上限，需要时另开工作单。
- **索引截断无独立状态**：正文超限截断通过预览降级说明与统计体现，`DocumentSummary` 未增加字段。
- **表格预览取舍**：非活动工作表的行列数返回 `None`（不为切表扫描整本工作簿）；CSV 每页请求会整文件扫描一次以给出精确总行数。
- **两字符查询**：按设计只匹配标题/描述/元数据，不匹配正文（FTS5 trigram 的既有取舍）。
- **测试配置**：`vite.config.ts` 已排除 `.scratch`，避免把其它工作区副本的测试当成本仓库测试；并行构建负载下用例超时放宽到 15s、`findBy*` 等待放宽到 3s（断言未放宽）。
